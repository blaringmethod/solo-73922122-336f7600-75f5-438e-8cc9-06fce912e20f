# 防火墙规则工作台（Firewall Rule Diff & Audit）

面向防火墙管理员的两个工具，共用同一套**有序 IPv4/TCP 规则**语义与精确切分引擎：

* **变更差分**（`/`）：上线前比对两份规则集，精确列出**新增放行**与**新增阻断**的全部流量区域；
* **规则有效性审计**（`/audit`）：粘贴一份有序规则集，精确计算每条规则真正**生效的区域**，
  区分**完全遮蔽** / **部分生效** / **完全生效**与 **allow/deny 动作冲突**，
  列出遮蔽来源与代表报文，辅助决定重排或删除。

均不做抽样：通过边界切分对整个流量空间做精确枚举。

## 规则语义

* 仅支持 **IPv4 + TCP**；
* 每条规则：`id`（同一份规则集内唯一的整数或字符串）、`source`/`destination`
  （严格 IPv4 CIDR，主机位为 0；全网 `0.0.0.0/0`，单机 `a.b.c.d/32`）、
  `portRange`（目的端口闭区间 `[下界, 上界]`，0–65535 整数）、
  `action`（小写 `allow` / `deny`）；
* 按数组顺序匹配，**首条命中生效**；全部未命中即**默认拒绝**（DEFAULT DENY）；
* 每份规则集最多 **20 条**。

```json
[
  {
    "id": 1,
    "source": "10.0.0.0/8",
    "destination": "172.16.0.0/12",
    "portRange": [80, 443],
    "action": "allow"
  }
]
```

## 快速启动（Docker Compose）

```bash
docker compose up --build
# 浏览器打开 http://127.0.0.1:8000
```

端口默认只绑定宿主机回环地址（`docker-compose.yml` 中
`127.0.0.1:8000:8000`）。需要对局域网开放时改为 `"8000:8000"`。
容器内置健康检查，访问 `/api/health` 探活。

本地直接运行（无需 Docker）：

```bash
pip install -r requirements.txt
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

## 页面与接口

顶部导航在两个页面间切换：**变更差分**（`/`）与**规则有效性审计**（`/audit`）。

### 变更差分（`GET /`）

* 两个编辑框分别粘贴旧、新规则；
  * **分析变更**：调用差分接口并渲染结果；
  * **载入重叠规则示例**：一键载入内置的重叠 CIDR / 端口区间示例；
  * **清空输入与结果**。
* `GET /api/example`：返回可直接载入的差分示例 JSON；
* `POST /api/analyze`：请求体 `{"old": "<旧规则JSON文本>", "new": "<新规则JSON文本>"}`；
  * 成功：`{"ok": true, "result": {...}}`；
  * 输入无效：HTTP 400，`{"ok": false, "errors": [...]}`，每条错误标明
    所属规则集（`sheet`）、第几条规则（`ruleIndex`）、字段（`field`），
    JSON 语法错误另附行列号（`line`/`col`）。前端收到错误会**清除旧结果**。

### 规则有效性审计（`GET /audit`）

* 单个编辑框粘贴一份有序规则集；
  * **开始审计**：调用审计接口并渲染每条规则的生效情况；
  * **载入遮蔽示例**：一键载入同时含完全遮蔽（冲突 / 冗余）、部分生效、
    完全生效四种情形的内置示例；
  * **清空输入与结果**。
* `GET /api/audit/example`：返回可直接载入的审计示例 JSON（`{"rules": [...]}`）；
* `POST /api/audit`：请求体 `{"rules": "<规则集JSON文本>"}`；
  * 成功：`{"ok": true, "result": {...}}`；
  * 输入无效：HTTP 400，错误结构同上（`sheet` 固定为 `"rules"`），
    前端收到错误会**清除旧结果**。

## 审计输出如何读

汇总条给出：规则总数、完全生效 / 部分生效 / 完全遮蔽条数、存在动作冲突的
规则数、冗余可删规则数。每条规则一张卡片：

* **状态**：`fully-effective`（完全生效）/ `partially-effective`（部分生效）/
  `fully-shadowed`（完全遮蔽——永远不会命中任何报文）；
* **声明区域 vs 真正生效**：声明的源/目的/端口范围、声明报文数、生效报文数与
  百分比、被遮蔽报文数与百分比（生效 + 被遮蔽 ≡ 声明，精确守恒）；
* **生效区域**：若干互不重叠的三维长方体块，每块附**代表报文**
  （各区间最小端点），该区域内任意报文都首条命中本规则；
* **被遮蔽区域**：按**遮蔽来源**（前置规则编号、id、动作）分组的区域块，
  每块标注 `conflict`（前置规则动作相反，**allow/deny 动作冲突**）或
  `same-action`（动作一致，属冗余覆盖），并附代表报文——该报文实际首条命中
  的是前置规则；
* **建议**：完全遮蔽且冲突 → 移到遮蔽规则之前或删除；完全遮蔽且动作一致 →
  冗余，删除不影响任何判定；部分生效 → 前移 / 拆分 / 缩小范围。

## 输出如何读（差分）

结果分「新增放行」「新增阻断」两组，每组由若干**互不重叠的三维长方体区域**组成：

* **源地址区间**、**目的地址区间**（闭区间；若恰好对齐一个 CIDR 会同时标注）、
  **目的端口区间**（闭区间）；
* **覆盖报文数** = 源地址数 × 目的地址数 × 端口数（以字符串返回，避免 32 位整数溢出）；
* **示例报文**：取三个区间的最小端点组成的具体 TCP 报文（源 IP → 目的 IP : 端口）。
  同一区域内任意报文的命中结果恒定，因此该报文即代表整块；
* **变更前 / 变更后判定**：分别给出命中规则的编号 `ruleId`、顺序 `ruleOrder`
  与动作；未命中任何规则时标记 `defaultDeny: true`、`ruleId: "DEFAULT-DENY"`。

## 精确性原理（无抽样）

1. 收集规则全部边界（CIDR 的首尾地址、端口区间端点），把整个流量空间
   `源 IPv4 × 目的 IPv4 × 端口 0..65535` 切分为若干**基本单元**；在任一单元
   内部，每条规则对整个单元要么全命中、要么全不命中，故单元内每个报文的
   命中规则恒定。
2. 对每个基本单元按「顺序扫描、首条命中」计算命中规则（未命中记为默认拒绝）。
3. **差分**：把 `(旧命中, 新命中)` 完全相同且相邻的单元贪心合并为长方体区域，
   仅保留动作发生变化的区域，并按变化方向分成新增放行 / 新增阻断；
   输出区域两两互不重叠，且其并集恰好等于所有新旧判定不一致的流量。
4. **审计**：把首条命中相同的相邻单元合并，即得每条规则的**生效区域**；
   在每条规则的声明区域内，首条命中为某条前置规则的单元按该前置规则分组
   合并，即得**被遮蔽区域**及其遮蔽来源。对每条规则：
   生效区域 ∪ 被遮蔽区域 = 声明区域，且两两互不重叠。

实现见 `app/engine.py`；`tests/` 中的穷举测试会在受限子空间内**逐点枚举**
（非抽样）核对每个报文点与输出区域的归属、互不重叠性、报文计数及代表报文判定。

## 目录结构

```
.
├── app/
│   ├── __init__.py
│   ├── engine.py          # 校验 + 边界切分 + 精确差分 / 有效性审计（核心，无第三方依赖）
│   ├── example_data.py    # 内置重叠规则示例（差分）与遮蔽冲突示例（审计）
│   ├── main.py            # FastAPI 路由（两个页面 + 两组 JSON API）
│   └── static/
│       ├── index.html     # 变更差分页（原生 HTML/CSS/JS，无构建步骤）
│       └── audit.html     # 规则有效性审计页
├── tests/                 # pytest：48 个用例（校验、语义、穷举精确性、API）
├── Dockerfile
├── docker-compose.yml
├── requirements.txt
└── pytest.ini
```
